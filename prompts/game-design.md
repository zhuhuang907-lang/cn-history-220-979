# 提示词：从时代到游戏概念

## 用途

把一个历史时代段落转成可玩的游戏概念、核心循环与 MVP 范围。

## 提示词

```text
你在 cn-history-220-979 仓库中工作。请先读 CLAUDE.md 和 docs/game-design/README.md。

任务：基于 {{PERIOD}} 设计一个历史策略/角色扮演游戏概念。
目标平台：{{PC / 手游 / 桌游 / 文字原型}}
目标体验：{{权谋 / 战争 / 生存 / 经营 / 叙事}}
玩家位置：{{君主 / 将领 / 地方官 / 商人 / 流民}}
规模：{{小团队 MVP / 中型 / 大型}}

输入：
- data/periods.json 中的 {{PERIOD}} 段落
- data/game/factions.json、characters.json、events.json、locations.json
- 需要时用 python scripts/search.py 查原文

输出：
## 1. 一句话概念
（谁、在什么处境、做什么、为什么有趣）

## 2. 核心循环
（3–5 步，说明资源如何流动、压力如何升级）

## 3. 时代压力
- 政治：
- 军事：
- 经济：
- 社会/宗教：
- 外部势力：

## 4. 可玩阵营（3–5 个）
| 阵营 | 核心优势 | 致命弱点 | 胜利路径 | 历史钩子 |
|---|---|---|---|---|

## 5. 地图与关键地点（5–8 个）
| 地点 | 类型 | 战略价值 | 相关事件 |
|---|---|---|---|

## 6. 事件链（5–8 个节点）
（用 events.json 的 id；说明触发条件、玩家选择、后果）

## 7. 核心系统
- 资源：
- 合法性：
- 军事：
- 外交：
- 人物关系：

## 8. MVP 范围
- 必须做：
- 可以砍：
- 暂不做：

## 9. 史实/设计/创作分层
- 史实依据：
- 设计抽象：
- F 级创作：

规则：
- 每个阵营必须有弱点，不能有唯一最优解。
- 事件必须引用 data/game/events.json 中存在的 id，或明确标为“新增建议”。
- 不得把演义情节写成史实。
- 数值用区间/量级，不伪造精确数字。
```

## 示例变量

```yaml
PERIOD: 五代
PLATFORM: PC
EXPERIENCE: 权谋 + 战争
PLAYER: 君主
SCOPE: 小团队 MVP
```
