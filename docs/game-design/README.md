# 游戏设计指南

本目录说明如何把 `cn-history-220-979` 的史料与结构化数据转化为游戏世界、人物、事件与玩法。它不是一套固定的数值表，而是一组**可复用的设计方法**。

## 三层结构

设计时始终区分三层，避免把“史料”“抽象”“创作”混为一谈：

### 1. 史实层（A/B/C）

来自 `data/game/` 与 `texts/` 的可核查信息：

- 政权起止年、都城、疆域
- 人物生卒、籍贯、所属、关系
- 事件年份、地点、参战方、结果
- 制度、术语、地名

这一层必须能回溯到 `sources` 中的书目 ID 与卷次。

### 2. 抽象层（设计）

为了玩法做的简化与量化：

- 政权强弱项、经济/军事风格
- 人物属性、性格标签、角色定位
- 事件难度、持续时间、可选分支
- 地图节点、补给线、兵力上限

这一层是**设计建议**，可以按玩法调整，但不能反过来覆盖史实层。

### 3. 创作层（F）

小说、演义、影视、游戏原创的桥段、台词、形象：

- 人物外貌、语气、传奇事迹
- 虚构对话、爱情线、复仇线
- 超自然元素、戏剧化反转

这一层必须标 `F`，不得作为史实依据；如果玩家可能误认，应在 UI 或文档中明确提示。

## 数据到游戏的流水线

```text
data/periods.json           → 时代选择 / 战役章节
data/game/factions.json     → 阵营、外交、资源风格
data/game/characters.json   → 人物、关系网、招募池
data/game/events.json       → 事件链、历史节点、触发器
data/game/locations.json    → 地图节点、关隘、都城
data/game/glossary.json     → 制度、兵种、改革、术语解释
data/game/disambiguation.json → 同名实体消歧、剧本选择
texts/                      → 细节、台词、考证、扩展事件
```

推荐顺序：

1. **选时代**：从 `periods.json` 选一个段落，确定开局年与核心矛盾。
2. **选政权**：从 `factions.json` 选 2–5 个可玩/不可玩阵营，检查盟友/敌人关系。
3. **搭地图**：用 `locations.json` 的都城、关隘、河流、战场构建节点图。
4. **铺人物**：用 `characters.json` 的阵营、角色、关系、事件建立初始班底。
5. **写事件链**：用 `events.json` 的年份、类型、参战方、结果做历史节点。
6. **补细节**：用 `search.py` 检索原文，补台词、数字、地名、制度。
7. **做抽象**：设计数值、资源、胜负条件，标注哪些是史实、哪些是设计。

## 设计原则

1. **历史是约束，不是剧本**：让玩家可以偏离历史，但偏离要有代价与后果。
2. **每个阵营都有合理性**：不要用单一“正义/邪恶”标签；用利益、制度、地理、合法性解释行为。
3. **失败也有叙事**：亡国、兵变、被俘、流亡都可以是玩法内容。
4. **数据可追溯**：每个关键设定至少有一个 `sources` 条目；玩家可在图鉴中查看出处。
5. **避免时代错置**：不要把晚出的制度、技术、民族标签提前使用。
6. **数值服务体验**：史料中的兵力、户数常被夸大，游戏数值应重新标定，并在注释中说明。
7. **同名先消歧**：魏、晋、唐、周、梁、汉、燕等先查 `disambiguation.json`。

## 最小可行原型（MVP）

如果只想快速做一个可玩的原型：

- **范围**：一个时代 + 2 个阵营 + 5 个地点 + 10 个人物 + 5 个事件。
- **推荐开局**：
  - 三国：曹魏 vs 蜀汉，聚焦汉中—祁山—五丈原。
  - 中唐：唐廷 vs 河朔三镇，聚焦魏博、成德、卢龙。
  - 五代：后周 vs 北汉 + 契丹，聚焦高平之战与禁军改革。
  - 宋初：北宋 vs 南唐/吴越，聚焦“先南后北”。
- **核心循环**：招募 → 补给 → 行军 → 决战 → 战后整编。
- **历史节点**：用 3–5 个 `events.json` 条目做时间轴，玩家选择改变结果。
- **胜负**：不只看灭国，也看正统、民生、财政、人才存续。
