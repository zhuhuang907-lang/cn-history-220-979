# 平衡、数值与史料审查

本文说明如何把史料中的数字与描述转成游戏数值，同时保持可信度、可追溯性与时代一致性。

---

## 1. 数值抽象原则

### 1.1 史料数字不能直接当游戏数值

古籍中的兵力、户数、人口、距离常有：

- 夸大（“号称百万”）
- 约数（“数万”“十余万”）
- 传抄错误
- 不同统计口径（户/口/丁/兵）
- 宣传与威慑目的

因此：

1. 先记录**史载数字**与出处。
2. 再给出**设计数字**，并说明换算假设。
3. 不要用“精确到个位”的数字伪装史实。

### 1.2 推荐量级

| 项目 | 史载常见范围 | 游戏建议 |
|---|---|---|
| 全国兵力 | 数十万至百万（多夸大） | 以“军团”为单位，不逐兵模拟 |
| 单场战役 | 数万至数十万 | 3–10 个单位，每单位 5k–20k |
| 城池人口 | 数千至数十万 | 用 1–10 级规模，不写具体人口 |
| 行军速度 | 日行 20–40 里（大军更慢） | 按节点/回合，不按公里 |
| 粮草 | 数月为极限 | 用“补给天数/粮道容量” |
| 战争持续时间 | 数月到数年 | 用阶段事件，不逐日 |

### 1.3 资源系统

中古战争的关键资源：

- **粮草**：决定出兵规模与持续时间。
- **兵源**：编户、部曲、牙兵、蕃兵、募兵。
- **财政**：田赋、盐铁、商税、掠夺。
- **合法性**：天命、血统、禅让、战功、民生。
- **人才**：士族、寒人、武将、幕僚、宦官。
- **情报**：斥候、间谍、降将、地方豪强。
- **民心**：灾荒、赋役、战乱、宗教。

不要只做“金币+兵力”；至少加入粮草与合法性，才能表现中古政权的约束。

## 2. 战斗抽象

### 2.1 兵种

| 兵种 | 优势 | 劣势 | 历史语境 |
|---|---|---|---|
| 步兵 | 守城、结阵、成本低 | 机动差 | 郡国兵、府兵、募兵 |
| 骑兵 | 机动、冲击、追击 | 贵、依赖草料 | 匈奴、鲜卑、突厥、契丹、沙陀 |
| 水军 | 江河控制、运输 | 受地形限制 | 江东、南朝、吴越 |
| 弓弩 | 远程、守城 | 近战弱 | 汉唐军队标配 |
| 牙兵 | 精锐、政变 | 难控制、易反噬 | 唐末五代藩镇 |
| 蕃兵 | 骑射、边疆 | 忠诚不稳 | 唐、五代、宋初 |
| 乡兵 | 本土防御、成本低 | 野战弱 | 州郡、团练 |

### 2.2 战斗修正

建议用少量修正，而不是复杂公式：

- 地形：关隘、河流、山地、平原。
- 补给：粮道长度、是否被断。
- 士气：合法性、连胜/连败、主将、赏罚。
- 兵力：不要线性叠加，用边际递减。
- 兵种克制：骑克步（平原）、水克渡口、弓克攻城。
- 天气/季节：雨季、严寒、疫病。

### 2.3 胜负与代价

历史战争很少“全歼”。建议：

- 败方可以撤退、溃散、投降、被俘。
- 胜方也会损兵、缺粮、失民心。
- 攻城战破坏城市与人口。
- 屠杀、劫掠会带来短期收益与长期合法性损失。

## 3. 时间与节奏

### 3.1 时间尺度

| 玩法 | 时间单位 | 适用 |
|---|---|---|
| 战略 | 季/年 | 内政、外交、改革 |
| 战役 | 旬/月 | 行军、围城、决战 |
| 战术 | 时辰/日 | 单场战斗 |

不要用同一时间尺度处理内政与战斗；分层切换更符合历史体验。

### 3.2 历史节点

用 `events.json` 的年份做“历史压力”：

- 到某年，某事件可能触发（不是必然）。
- 玩家改变条件，事件可提前、延后、缩小、取消。
- 事件触发后，改变后续事件链与人物关系。

### 3.3 人物寿命

- 生卒年来自史料，不确定时用 `null` 或“约”。
- 不要为了剧情强行延长/缩短寿命；如需，标为 `F` 级创作。
- 关键人物早逝可以成为玩法转折（柴荣、郭威、孙策）。

## 4. 时代一致性

### 4.1 常见时代错置

| 错误 | 正确做法 |
|---|---|
| 把“北京”当唐代北京 | 唐代幽州，今北京；用 `modern_name` |
| 把“节度使”用于东汉 | 东汉用州牧、郡守；节度使始于唐 |
| 把“科举”用于魏晋 | 魏晋用九品中正、察举 |
| 把“火药武器”用于唐初 | 唐末才逐渐用于军事 |
| 把“民族国家”概念用于中古 | 用政权、部族、藩镇、朝廷 |
| 把“省”当唐代行政区 | 唐用道、州、县；元以后才有行省 |
| 把“普通话”当古代口语 | 用当时称谓、官话、方言差异 |
| 把“骑兵万能”套用所有政权 | 南方水网、山地限制骑兵 |

### 4.2 称谓与礼仪

- 君主自称、臣下称谓、避讳、谥号、庙号要区分。
- 不要用现代“皇帝陛下”“将军”一刀切。
- 不同政权、不同场合称谓不同；不确定时用中性描述。

### 4.3 宗教与民族

- 使用历史语境中的称谓，不用现代贬义/褒义标签。
- 佛教、道教、祆教、摩尼教、景教在不同时期地位不同。
- 民族政权内部也有多元群体，不要单一化。

## 5. 可信度与引用

### 5.1 数据字段

每条游戏数据应有：

```json
{
  "sources": ["JIUWUDAISHI", "XINWUDAISHI", "ZIZHITONGJIAN"],
  "reliability": "A"
}
```

- `sources`：目录中存在的书目 ID。
- `reliability`：A / A/B / B / B/C / C / M / F / D。
- 设计层描述（数值、强弱项）不需要单独来源，但应说明是设计抽象。

### 5.2 引用格式

```text
《旧五代史》卷一百一十四（周书五·世宗纪一），
Wikisource 转录（CC BY-SA 4.0），
https://zh.wikisource.org/wiki/舊五代史/卷114
```

游戏内图鉴可以简化为：

```text
史料：旧五代史 · 周世宗纪
可信度：A
```

但后台数据必须保留完整 `sources` 与卷次。

### 5.3 冲突与不确定

- 多种史料冲突时，保留异说，不要强行统一。
- 年份不确定写“约”“一说”。
- 人物关系不确定写“传”“疑”。
- 数字不确定写“史载”“号称”。

## 6. 审查流程

### 6.1 数据审查

```bash
python scripts/build_game_data.py   # schema + 引用完整性
python scripts/validate.py          # 全库一致性
python -m unittest discover -s tests
```

### 6.2 内容审查

- [ ] 事件类型是否使用 schema 枚举？
- [ ] 人物阵营、事件参战方是否存在？
- [ ] 地点 `id` 是否存在？
- [ ] `sources` 是否都是目录中的书目？
- [ ] 是否有 `F` 级内容未标注？
- [ ] 是否有现代版权文本被误引？
- [ ] 是否有时代错置的官称、地名、技术？
- [ ] 数值是否有“史载/设计”区分？
- [ ] 同名实体是否已消歧？

### 6.3 发布前检查

- [ ] 游戏内图鉴显示来源与可信度。
- [ ] 玩家可以看到“史实/设计/创作”标签。
- [ ] 失败、亡国、被俘等负面结局也有内容。
- [ ] 没有把某一政权/民族简单妖魔化。
- [ ] 没有伪造引文、卷次、年份。

---

## 7. 平衡检查表

- [ ] 每个阵营是否有明确优势与弱点？
- [ ] 是否存在“唯一最优解”？如果有，是否有代价？
- [ ] 战争是否受粮草、季节、地形限制？
- [ ] 内政、外交、军事是否互相牵制？
- [ ] 失败是否有翻盘或体面结束的可能？
- [ ] 历史事件是否可被玩家改变，但改变有后果？
- [ ] 数值是否随时代变化，而不是一套通吃？
- [ ] 后期是否避免“滚雪球”导致无挑战？
- [ ] 是否给弱势阵营/小国留下生存策略？
